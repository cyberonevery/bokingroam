SKRIP DAN PANDUAN PRESENTASI UAS PEMROGRAMAN WEB
Proyek: BookingRoam (Room Booking System)

TIPS UMUM UNTUK PRESENTASI:
- Bicara dengan tenang, santai, namun tetap profesional. Jangan terlihat membaca teks kaku.
- Gunakan transisi kata seperti "Selanjutnya...", "Seperti yang Bapak/Ibu lihat...", "Di sisi backend...".
- Bagi tugas presentasi. Misalnya: Anggota A menjelaskan sisi User, Anggota B menjelaskan sisi Admin, Anggota C menjelaskan sisi teknis/API.

PERSIAPAN WAJIB (H-1 / Sebelum Maju ke Depan):
1. Pastikan server Backend menyala: buka terminal, jalankan npm run dev di folder backend.
2. Pastikan server Frontend menyala: buka terminal baru, jalankan npm run dev di folder frontend.
3. Siapkan Tab Browser: 
   - Tab 1: Aplikasi BookingRoam (http://localhost:5173 atau 5174) dalam posisi halaman Login.
   - Tab 2: GitHub repositori kelompok (langsung buka tab Commits atau Contributors).
4. Siapkan Akun: Ingat baik-baik 1 akun User dan 1 akun Admin untuk demo agar tidak salah ketik saat live.

SESI 1: DEMO APLIKASI DAN TEKNIS (WAKTU: 4 MENIT)

[00:00 - 00:45] Pembukaan dan Login (Oleh Pembicara 1)
(Aksi: Tampilkan layar halaman Login)
Pembicara 1: 
"Selamat pagi/siang Bapak/Ibu Dosen. Kami dari kelompok [Sebutkan Nama Kelompok, misalnya Kelompok 3] yang beranggotakan [Sebutkan Nama Anggota]. Pada kesempatan kali ini, kami akan mendemokan proyek akhir kami yaitu BookingRoam. 

BookingRoam adalah sistem informasi manajemen pemesanan ruangan. Aplikasi ini kami kembangkan menggunakan framework Svelte di sisi frontend, dan Express.js di sisi backend.

Pertama, mari kita mulai dari fitur autentikasi. Saya akan mendemokan login sebagai User biasa.
(Aksi: Ketik email dan password, lalu klik Login)
Di belakang layar, ketika saya menekan tombol login, frontend mengirimkan HTTP POST request ke backend Express kami. Backend akan memvalidasi password dengan hash bcrypt dan mengembalikan JWT Token. Token ini kami simpan di local storage untuk menjaga session user."

KISI-KISI DAN CONTEKAN LIVE CODING UNTUK KELOMPOK
(Jangan dibaca keras-keras saat presentasi! Ini pegangan kelompok)

JIKA DOSEN MINTA UBAH TAMPILAN ATAU UI (SVELTE):
1. Mengubah menu sidebar (misal: Coba ganti tulisan 'Katalog Ruangan' jadi 'Daftar Kelas'): 
   Buka file frontend/src/components/Sidebar.svelte
2. Mengubah warna tombol atau style utama (misal: Coba warna tombol primernya dibikin merah): 
   Buka file frontend/src/app.css (Cari variabel --primary).
3. Mengubah tabel admin (misal: Coba hilangkan kolom 'Kapasitas' dari tabel): 
   Buka frontend/src/pages/RoomManagement.svelte
4. Mengubah State (misal: Gimana cara kalian simpan session user?):
   Tunjukkan file frontend/src/stores/authStore.js

JIKA DOSEN MINTA UBAH LOGIKA ATAU API (EXPRESS NODE.JS):
1. Mengubah validasi Controller (misal: Coba buat kalau jam pinjam sama jam selesai itu kebalik, keluar pesan error khusus): 
   Buka file backend/src/controllers/reservation.controller.ts (cari fungsi createReservation).
2. Mengubah Logic Ruangan (misal: Coba tambahkan response supaya kalau get room, kapasitasnya ikut ditampilkan tapi dikali 2): 
   Buka file backend/src/controllers/room.controller.ts (cari fungsi getRooms).
3. Mengubah Database Schema (misal: Di mana kalian definisikan tipe data field MySQL?): 
   Buka file backend/src/db/schema.ts
4. Routing (misal: Di mana letak endpoint '/api/rooms'?): 
   Tunjukkan file backend/src/routes/room.routes.ts

STRATEGI SAAT LIVE CODING:
- Tarik napas, jangan panik.
- Dosen hanya mengetes apakah kalian tau letak kodenya dan paham alurnya.
- Pakai fitur Search (Ctrl + P untuk cari nama file).
- Tiap merubah kode Svelte/Express, jangan lupa SAVE (Ctrl + S). Hasilnya akan otomatis ke-refresh di browser, segera tunjukkan ke dosen efeknya!
